| 2026-11-19 | **Trust pins are stored in the host data dir, not in the repo.** The old steering example kept `trust = "sha256:..."` inside `pumpkin-shell.toml`; whoever can edit the policy could edit its pin, and a file cannot contain its own hash. | 2026-11-19 | Policy schema v1 is small on purpose: `version`, `mode`, `[rules.<ID>] action`. Ordered `alert` < `ask` < `block`; `monitor` < `enforce`. | 2026-11-19 | User policy file: refused when others can write it, allowed when only the group can. On Linux Mint and Ubuntu `umask` is 002 and every user has a private group, so ordinary files are 0664 (found when a test using a freshly created file failed). Key files and the key directory stay strict: no group or other access | Tested here |
| 2026-11-19 | Signed log format: `ts` is Unix time in **milliseconds** (integer); one file per session; `prev` is the SHA-256 of the previous *signed* line (the first line chains to a hash of the session id); each line must be byte-for-byte the canonical form, so spacing, field order, duplicate or unknown keys and CRLF all fail; entries, checkpoints and the genesis hash are signed or hashed under different domain prefixes; text fields are cut to 1024 bytes so hostile input cannot make logging fail. The checkpoint is a separate file, `<log>.checkpoint`, with the entry count and the hash of the last line | Closes tail truncation, the one thing a chain cannot detect |
| 2026-11-19 | `log verify` takes the public key from the key directory (`--key-dir`, default the data dir), never from the log, and never creates a key. A log without a checkpoint **fails** unless `--allow-open` is given, because deleting the tail and the checkpoint together would otherwise look clean. Exit codes: 0 verified, 1 verification failed, 2 could not check | An attacker who edits the log must not also choose the key |
| 2026-11-19 | `policy check [PATH]` was added to the CLI (PRD updated) so the merge and `POL-UNTRUSTED` can be run and demonstrated. `trust` also prints which entries will be ignored | tech.md: each task ends with a runnable demo |
| 2026-11-19 | Known limits of Phase 7: (1) whoever holds the signing key can forge a log, so the signatures only prove tampering by the sandbox, as PRD §11 says; keeping the data dir out of the sandbox is Phase 8's job; (2) on Windows the key files get their folder's ACL and are not hardened (Phase 16); (3) the seed is not wiped from memory after use; (4) `ts` is recorded but not checked for order; (5) the file lock is advisory; (6) a closed session cannot be reopened, and a crashed one has no checkpoint; (7) `log` has no viewer yet | Honest limits |
