Fix: `relay::pipe` shuts down the Unix write side when the client side ends (test `when_the_client_closes_the_far_end_sees_end_of_stream`), and `server::serve` reads each connection in its own thread, with the upstream work still one at a time behind a lock (test `a_client_that_sends_nothing_does_not_hold_up_the_next_request`). (2) The mirror checks a file's checksum before it sends the first byte, so a 17.6 MB uv wheel (8.3 s to download from PyPI on this machine) can take longer than pip's default 15 s socket timeout. The sandbox now sets `PIP_TIMEOUT` and `UV_HTTP_TIMEOUT` to 120 s (listed in the uv environment reference, docs.astral.sh/uv/reference/environment). Files over the 128 MiB cap are still refused. |
