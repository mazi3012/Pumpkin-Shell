| 2026-11-21 | **How protected paths are enforced (10.1).** Measured with bubblewrap 0.9.0 on this machine before designing: (1) a bind mount over a missing path creates the mount point in the host repo; (2) a mount does not protect its parent, so `mv .git .git2` succeeded and let a fresh unprotected `.git/hooks` be made; (3) a rename onto a mounted file fails with EBUSY; (4) a symlink as the destination makes bwrap fail. So: staged copies are bound over the protected paths, parents are bound over themselves, mount points that were missing are made by the host and removed at exit (also on any failure, through `Drop`), and symlinks are refused up front. `rm -rf` on a protected path empties only the staged copy and then fails with EBUSY; the repo is untouched. **Replaces the PRD's "host inotify watcher"**: no `notify` dependency and no race, because nothing can be written to a protected path outside staging | Tested in the real sandbox; PRD FR-WS intent kept |
